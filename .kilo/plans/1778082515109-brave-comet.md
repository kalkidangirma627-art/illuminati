# Plan: Restore Missing Dashboard Features

## Problem Analysis

The codebase has **two parallel frontend systems** that are disconnected:

1. **Static HTML + Vanilla JS** (`dashboard.html` + `dashboard.js`) — This is what Vercel serves. It handles **agent** and **member** roles but has **NO admin dashboard**. The agent view shows member cards and requirement editing. The member view shows requirement progress cards.

2. **React SPA** (`src/App.jsx` + React components) — This has fully-built `AdminDashboard.jsx`, `AgentDashboard.jsx`, and `MemberDashboard.jsx` components, but they are **never reached** because Vercel serves the static HTML dashboard, not the React app. Additionally, the React `AdminDashboard.jsx` calls **5 admin API endpoints that don't exist** in `server.js`.

### What's Missing

**Backend (server.js):**
- No admin API routes at all (`/api/admin/*`)
- AdminDashboard.jsx calls these missing endpoints:
  - `GET /api/admin/users` — list all users
  - `POST /api/admin/approve/:id` — approve pending user
  - `POST /api/admin/reject/:id` — reject pending user
  - `DELETE /api/admin/users/:id` — delete user
  - `POST /api/admin/assign` — assign agent to member

**Frontend (static HTML dashboard):**
- No admin view — `dashboard.js` only handles `agent` and `member` roles
- Admin users who log in see the agent/member dashboard instead of an admin panel
- No member cards with document processing, biometric legitimacy, etc. for admin oversight
- No agent activity tracking for admin

**React components issues:**
- `MemberDashboard.jsx` uses hardcoded static data instead of fetching from API
- `AdminDashboard.jsx` uses relative `/api` paths (needs to point to Railway)

## Solution Architecture

Since the static HTML dashboard (vanilla JS) is what Vercel actually serves, I will **enhance the existing static HTML system** rather than trying to switch to the React SPA. This avoids a complete frontend rewrite.

### Changes

#### 1. Backend: Add Admin API Routes to `server.js`

Add 5 new endpoints:
- `GET /api/admin/users` — returns all users with their requirements
- `POST /api/admin/approve/:id` — sets user status to "approved"
- `POST /api/admin/reject/:id` — sets user status to "rejected"
- `DELETE /api/admin/users/:id` — deletes user and their requirements
- `POST /api/admin/assign` — sets `assignedAgentId` on a member

All protected by `authenticate` + `requireRole('admin')` middleware.

#### 2. Frontend: Enhance `dashboard.js` with Admin Support

Add admin role handling to the existing vanilla JS dashboard:
- `setupAdminUI()` — fetches all users, renders admin panel with:
  - KPI strip: pending count, approved count, total users, agents count, members count
  - Tab-based filtering: All / Pending / Approved / Rejected
  - User cards showing: name, email, role, status, balance, assigned agent
  - For pending users: Approve + Reject buttons
  - For approved members: Assign agent dropdown
  - For all users: Delete button
  - Search by name/email/role
- `renderAdminUserCard()` — renders individual user cards with action buttons
- `renderAgentMemberCards()` — for agent view, show member cards with:
  - Member name, email, avatar
  - Requirement progress (Doc Processing, Biometrics, First Income, Doc Transaction, Payment)
  - Status indicators (completed/in-progress)
  - Click to expand and edit requirements
- `renderMemberCards()` — for member view, show their own requirement cards with:
  - Document Processing status
  - Biometric Legitimacy status
  - First Income Received status
  - Document Transaction to HQ status
  - Payment status
  - Progress bars and completion indicators

#### 3. Frontend: Enhance `dashboard.html` Admin Layout

The existing `dashboard.html` layout (nav + card grid) works well for agent/member views. For admin, we need:
- Same nav bar with admin-specific controls
- KPI summary strip at top
- Tab bar for filtering (All/Pending/Approved/Rejected)
- User cards grid below

This can be done within the existing `dashboard.html` structure by showing/hiding admin-specific elements based on role.

#### 4. Fix `MemberDashboard.jsx` (React) — fetch from API

Update to fetch requirements from `/api/member/requirements` instead of using hardcoded data. Also fix API base URL to point to Railway.

#### 5. Fix `AdminDashboard.jsx` (React) — fix API base URL

Change from relative `/api` to `https://illuminati-production.up.railway.app/api` so it works when served from Vercel.

## Implementation Order

1. **Backend**: Add all 5 admin API routes to `server.js`
2. **Frontend**: Add admin role UI to `dashboard.js` (setupAdminUI, renderAdminUserCard, etc.)
3. **Frontend**: Enhance agent member cards in `dashboard.js` to show requirement details
4. **Frontend**: Enhance member cards in `dashboard.js` to show document/biometric/payment status
5. **Frontend**: Update `MemberDashboard.jsx` to fetch from API
6. **Frontend**: Update `AdminDashboard.jsx` API base URL
7. **Test**: Verify all three roles work correctly
8. **Build + Deploy**: Run `build.js` and push to git
