# MongoDB Atlas Setup and Backend Update Plan

## Objective
Create a new free MongoDB Atlas account accessible from anywhere and update the backend code to use it.

## Security Note
⚠️ **Warning**: Allowing access from `0.0.0.0/0` (anywhere) is not recommended for production environments as it poses security risks. This guide follows the user's specific request but for production use, consider restricting access to specific IP addresses or using VPC peering.

## Step-by-Step Guide

### Part 1: Create New MongoDB Atlas Account

#### Step 1: Sign Up for MongoDB Atlas
1. Go to [https://www.mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register)
2. Enter your email address and create a password
3. Complete the registration form (name, country, etc.)
4. Verify your email address

#### Step 2: Create a New Organization and Project
1. After logging in, you'll be prompted to create an organization
   - Organization Name: Enter a name (e.g., "MyWebsiteDB")
   - Click "Next"
2. Create a new project
   - Project Name: Enter a name (e.g., "lumosine-clone-db")
   - Click "Create Project"

#### Step 3: Build a Free Tier Cluster
1. In your new project, click "Build a Database"
2. Choose the cloud provider and region:
   - Provider: AWS, Google Cloud, or Azure (choose one closest to your users)
   - Region: Select a region
3. Choose cluster tier:
   - Select "M0 Free" under the "Shared" tier
   - Cluster Name: Enter a name (e.g., "cluster0")
4. Click "Create Cluster"
   - Wait 5-7 minutes for cluster provisioning

#### Step 4: Configure Network Access (Global Access)
1. Once cluster is ready, go to "Network Access" in the left sidebar
2. Click "+ Add IP Address"
3. Choose "Allow access from anywhere"
   - This will automatically enter `0.0.0.0/0`
   - Add a comment like "Global access for website"
   - Click "Confirm"
4. Note: This makes your database accessible from any IP address

#### Step 5: Create Database User
1. Go to "Database Access" in the left sidebar
2. Click "+ Add New Database User"
3. Choose authentication method: "Password"
4. Enter:
   - Username: Choose a username (e.g., `website_user`)
   - Password: Generate a strong password or enter one
   - Click "Autogenerate Secure Password" if desired (save this password!)
5. Database User Privileges:
   - Grant "Read and write to any database" (or more specific if preferred)
6. Click "Add User"

#### Step 6: Get Connection String
1. Go to "Clusters" in the left sidebar
2. Click "Connect" on your cluster
3. Choose "Connect your application"
4. Select:
   - Driver: Node.js
   - Version: 4.1 or later
5. Copy the connection string - it will look like:
   ```
   mongodb+srv://<username>:<password>@cluster0.mongodb.net/myFirstDatabase?retryWrites=true&w=majority
   ```
6. Replace `<username>` and `<password>` with the credentials you created
7. Update the database name (`myFirstDatabase`) to something appropriate (e.g., `lumosine`)

### Part 2: Update Backend Code

#### Step 1: Create Environment File
1. In the project root, create a file named `.env`
2. Add your MongoDB connection string:
   ```
   MONGO_URI=mongodb+srv://website_user:your_password@cluster0.mongodb.net/lumosine?retryWrites=true&w=majority
   ```
3. Add JWT secret (generate a strong one):
   ```
   JWT_SECRET=your_super_secret_jwt_key_here_make_it_long_and_random
   ```
4. Save the file

#### Step 2: Update server.js
1. Open `server.js`
2. Line 10: The `dotenv.config()` line is already there - good
3. Line 17-18: Update to use environment variable:
   ```javascript
   const MONGO_URI = process.env.MONGO_URI || 'mongodb://fallback:fallback@localhost:27017/lumosine';
   ```
4. Line 16: Update JWT secret:
   ```javascript
   const JWT_SECRET = process.env.JWT_SECRET || 'fallback-secret-change-in-production';
   ```
5. The rest of the code should work unchanged as it uses these variables

#### Step 3: Update .gitignore (Important for Security)
1. Ensure `.gitignore` contains:
   ```
   # Environment variables
   .env
   .env.local
   .env.development
   .env.production
   ```
2. If not present, add these lines

#### Step 4: Test the Connection
1. Install dependencies if needed: `npm install`
2. Run the server: `node server.js`
3. Look for: "Connected to MongoDB Atlas" in the console
4. If you see "Cloud connection failed. Using Local Fallback.":
   - Check your `.env` file format
   - Verify network access is set to `0.0.0.0/0`
   - Confirm username/password are correct
   - Ensure cluster is not paused

#### Step 5: Update Vercel Deployment (if applicable)
1. If deploying to Vercel, you need to set environment variables there:
   - Go to your Vercel project dashboard
   - Settings → Environment Variables
   - Add:
     - Name: `MONGO_URI`
     - Value: [your connection string]
     - Environment: Production (and Preview/Development if needed)
   - Add:
     - Name: `JWT_SECRET`
     - Value: [your JWT secret]
     - Environment: Production (and Preview/Development if needed)
2. Redeploy your application

## Troubleshooting

### Common Issues:

   1. **Connection failed (Most Common)**:
      - **DNS Resolution Issue**: The `mongodb+srv://` protocol requires DNS SRV records. Some networks block or fail to resolve these.
        - **Fix**: Try using the standard connection string format instead:
          ```
          mongodb://kalkidangirma627_db_user:jFAghIZQJaBY3lmd@cluster0-shard-00-00.q1zcxji.mongodb.net:27017,cluster0-shard-00-01.q1zcxji.mongodb.net:27017,cluster0-shard-00-02.q1zcxji.mongodb.net:27017/lumosine?ssl=true&replicaSet=Cluster0-shard-0&authSource=admin&retryWrites=true&w=majority
          ```
        - Get this from Atlas → Connect → Connect your application → Driver: Node.js → Version: 4.0 or earlier (shows non-SRV format)
      - **Wait for propagation**: After changing IP whitelist in MongoDB Atlas, wait 2-3 minutes for changes to propagate globally
      - **Verify exact IP entry**: Double-check that the Network Access tab shows exactly `0.0.0.0/0` (no extra spaces or characters)
      - **Test with specific IP**: Temporarily remove `0.0.0.0/0` and add your current IP address (find it at https://whatismyipaddress.com) to rule out propagation issues
      - **Check connection string**: Verify your connection string in `.env` matches exactly what Atlas provides
      - **Check cluster status**: In MongoDB Atlas → Clusters, ensure your cluster is not paused (should show "Active" not "Paused")
      - **Test network connectivity**: Try connecting from a different network (mobile hotspot) to isolate local network/firewall issues
      - **Increase timeout**: If connection works but is slow, increase timeouts in server.js:
        ```javascript
        await mongoose.connect(MONGO_URI, { 
          serverSelectionTimeoutMS: 15000, 
          socketTimeoutMS: 60000 
        });
        ```
      - **Check for special characters**: If your password has special characters (@, :, /, ?, #, [, ], etc.), they may need URL encoding in the connection string
      - **Firewall/Antivirus**: Temporarily disable Windows Firewall or antivirus software to test if they're blocking the connection
      - **VPN/Proxy**: If using a VPN or proxy, try disabling it or connecting through a different endpoint

   2. **Authentication failed**:
      - Confirm username/password match exactly what you created in Database Access
      - Check for accidental spaces before/after credentials
      - Verify special characters in password are correct
      - Try resetting the password in Database Access if unsure

   3. **ECONNRESET errors**:
      - Network connectivity issues between your location and MongoDB Atlas
      - Try increasing timeout in mongoose.connect options
      - Test from different network to rule out local ISP/firewall blocking

   4. **Vercel deployment issues**:
      - Verify environment variables are set correctly in Vercel dashboard
      - Check Vercel logs for connection errors
      - Ensure `.vercelignore` doesn't accidentally exclude important files

## Maintenance Tips
1. Monitor your cluster usage in MongoDB Atlas (free tier has limits)
2. Consider setting up alerts for unusual activity
3. For production, replace `0.0.0.0/0` with specific IP addresses or VPC peering
4. Regularly rotate your MongoDB password and JWT secret
5. Keep your Node.js dependencies updated: `npm update`
